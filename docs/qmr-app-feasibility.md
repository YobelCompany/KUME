## 2. 자료 분석에서 드러난 문제점

1. **정상 범위가 고정 상수** — 두 화면의 "정상적 범위" 열이 완전히 동일(성별·나이·체형 무관). 사람마다 달라야 할 임상 지표(혈압·콜레스테롤 등)를 단일 범위로 판정.
2. **단위·산출 근거 부재** — "콜레스테롤 58.115", "혈액점도 48.51"처럼 mg/dL·cP 등 실제 단위가 아님. 실제 검사값으로 환산 불가.
3. **재현성 의문** — 촬영 시각 10:31과 10:32(1분 간격, 동일 인물 추정)의 값이 크게 다름:
   - 심근 혈액 소요량 0.262 → 0.41 (약 56% ↑)
   - 혈관 저항력 1.343 → 1.606
   - 뇌조직 혈액공급 8.557 → 7.962
   - 같은 사람·같은 순간의 측정이라면 임상 도구는 이런 편차를 허용하지 않음. (※ 동일인 여부는 사진만으로 확정 불가 — 확인 필요)
4. **측정 불가능한 항목을 측정** — 손바닥 접촉만으로 "중금속, 전립선, 뼈 밀도, 혈당, 알레르기"를 산출한다는 주장은 의학적으로 확립된 방법이 아님.
5. 검색 결과에서도 독립 검증·동료심사 문헌을 찾지 못함 (제조사 공식 문서 · 프로토콜 명세도 확인 불가).

## 3. 기술 타당성 (폰 연동)

### 3-1. 현재 구조 (추정, 실기 확인 전)
```
[손바닥 센서] → [USB 본체] → Windows PC ← [USB 인증키(동글)]
                              └ 분석 SW 4.7.0 (판매업체 판정 DB로 52종 리포트 생성)
```
판매처 설명상 Windows(XP~10) 전용, 소프트웨어 실행에 **블루 USB 인증키가 필수**.

### 3-2. 핵심 미지수 3가지
| # | 질문 | 확인 방법 |
|---|---|---|
| A | 본체가 **원시 센서값**을 내보내나, 이미 분석된 값을 내보내나? | PC 장치관리자·`lsusb`로 VID/PID, USB 시리얼(CH340/FTDI 등) 여부, 패킷 캡처 |
| B | 항목별 수치·정상범위·판정 로직이 **본체 펌웨어/동글/PC SW 중 어디**에 있나? | 동글 분리 시 동작, 본체 단독 데이터 출력 여부 |
| C | 프로토콜·SW 사용권이 **합법적으로 이용 가능**한가? | 공급사(제조사·한국 총판) 계약·SDK 문의 |

### 3-3. 연동 방식별 평가
| 방식 | 설명 | 난이도 | 평가 |
|---|---|---|---|
| **1. 리포트 import (PDF/HTML/ZIP)** | PC SW가 내보낸 리포트를 앱이 읽어 저장·추이 표시 | ★☆☆ | **가장 현실적.** 기기·SW 원형 유지, 법적 충돌 최소 |
| 2. PC 브리지 | PC에 작은 에이전트 → 서버/폰으로 결과 전송 | ★★☆ | 현장 센터용으로 가능 |
| 3. Android USB-OTG 직결 | 폰이 USB 호스트로 본체 직접 통신 | ★★★ | **프로토콜 확보 시에만** 가능. 동글 인증 우회는 저작권·계약 문제 |
| 4. BLE 어댑터(ESP32 등) | 본체↔USB↔어댑터↔블루투스↔폰 | ★★★ | 하드웨어 제작 필요, 전기안전·전파인증(KC) 별도 |
| 5. iOS 직결 | Lightning/USB-C 외부기기 직통신 | ★★★★ | MFi/드라이버 제약으로 **사실상 불가** (BLE 어댑터 경유만) |
| 6. 자체 센서 개발 | 같은 원리로 독자 하드웨어 | ★★★★★ | 과학적 근거 부재 상태에서 투자 부적합 |

> 판정 로직·정상범위가 PC SW 안에 있다면 앱이 값을 재현할 수 없고, 이를 역공학해 복제하는 것은 **저작권(컴퓨터프로그램 보호) 및 계약 위반 소지**가 큽니다. (상호운용 목적의 제한적 예외가 있으나 상업 앱 배포에는 법무 검토 필수)

3. **개인정보보호법** — 건강정보는 **민감정보**(별도 동의, 안전성 확보조치). 앱 출시 시 개인정보 영향평가·처리방침 필수.
